# Research notes — version-sensitive facts (verified Sep 2026)

Baseline for the worksheet: **Kubernetes v1.37** (released 2026-08-26, "Garhwal": 67 enhancements — 16 stable, 23 beta, 27 alpha, 1 deprecation). v1.38 is in progress.

Facts to state correctly (with the version where they became true):

- **DRA (Dynamic Resource Allocation): GA since v1.34** (Aug 2025), using structured parameters (KEP-4381). The old "classic DRA" with opaque parameters was removed earlier. DRA is the forward path for GPUs/accelerators; device plugins still exist but DRA is the modern answer. v1.37 additions: extended-resource requests served by a DRA driver (GA — a DeviceClass carries the resource name, no claim in the pod), device taints and tolerations plus DeviceTaintRule (GA), ResourceClaim `.status.devices` with network interface data (GA), standard `resource.kubernetes.io/numaNode` attribute (stable), resource health in pod status for device plugins and DRA (GA per the release blog's stable list; the kubelet DRA health gRPC API moved to v1). Beta, gate off by default: workload-level ResourceClaims (`DRAWorkloadResourceClaims`). Alpha: derived attributes (CEL), device compatibility groups, PreQueueingHint, node-allocatable resources via DRA, optional node operations.
- **kube-proxy nftables mode: GA in v1.33**. iptables remains the default mode on Linux, but since v1.37 kube-proxy warns when no mode is set because the default will move to nftables in a future release; nftables mode now drives the kernel over netlink (no `nft` binary on the sync path). **IPVS mode is deprecated** (KEP-5495): warning since v1.35, `KubeProxyIPVS` gate added in v1.37, disabled by default by v1.40, removed by v1.43. **kube-dns add-on deprecated** in v1.37 (no packages after v1.40); the `kube-dns` Service name stays.
- **Native sidecar containers** (init containers with `restartPolicy: Always`): introduced v1.28, **stable in v1.33**.
- **In-place pod resize (resize CPU/memory without restart): GA in v1.35.** Pod-level resources: beta and on by default since v1.34; pod-level resource managers (NUMA alignment on the pod budget) beta in v1.37 behind a gate that is off. In-place resize of init containers: GA in v1.37. Scheduler preemption for deferred resizes: alpha in v1.37.
- **Server-Side Apply**: GA since v1.22 — safe to describe as the standard mechanism.
- **API Priority and Fairness (APF)**: GA since v1.29.
- **ValidatingAdmissionPolicy (CEL, in-process admission)**: GA since v1.30; **MutatingAdmissionPolicy: GA in v1.36** (beta since ~v1.34). Webhooks remain widely used.
- **Gateway API**: standard channel mature; **v1.5 (2026): TCPRoute and UDPRoute moved to Standard**. Position Gateway API as the successor to Ingress (Ingress is frozen, not removed).
- **User namespaces: GA in v1.36.**
- **Declarative validation for K8s APIs: GA in v1.36** (internal API-machinery improvement — mention only if useful).
- **Server-side sharded list/watch: alpha in v1.36 and still alpha in v1.37** (KEP-5866, `ShardedListAndWatch` gate). Mechanism: a client passes `shardSelector` with `shardRange()` over a 64-bit FNV-1a hash of `metadata.uid` or `metadata.namespace`; the API server filters both list and watch at the source, so each replica of a sharded controller receives only its slice. It is a controller-sharding aid, not API-server cache partitioning. Do not present as default.
- **In-place Pod restart / container restart improvements**: v1.35 work.
- **Extended toleration operators (numeric comparisons): alpha in v1.35** — do not present as usable default.
- **EndpointSlices** replaced Endpoints as the scalable mechanism (Endpoints API deprecated ~v1.33).
- **Decoupled taint manager: stable in v1.34** (node lifecycle controller split — relevant to taint-eviction flow).
- **cgroup v2** is the node baseline: `failCgroupV1` defaults to true since v1.35, so the kubelet refuses to start on a cgroup v1 host without an explicit `failCgroupV1: false` override (KEP-5573). **Memory QoS: beta and on by default in v1.37** — `memory.min` from requests protects requested memory from reclaim; `memory.high` throttling applies only when `memoryThrottlingFactor` is set (default nil).
- etcd: v3 API, revisions/watch/lease model; watch cache in API server serves most watches.

Facts added for the principal's-lens pass (verified Aug 2026):

- **Service mesh / dataplane direction**: Istio ambient (sidecar-less) mode GA since Istio 1.24 (Nov 2024); by 2026 new mesh deployments default to sidecar-less/eBPF designs, with sidecar proxies persisting for L7-heavy cases. eBPF CNIs are consolidating the kernel dataplane. Sources: istio.io ambient GA; 2026 mesh-state industry coverage.
- **AI training schedulers**: Slurm-class schedulers still common for large dedicated training fleets (native gang/topology/fabric scheduling); Kubernetes closes the gap via DRA plus queueing/gang layers (Kueue, Volcano — quota/admission and gang scheduling respectively, often layered). HPC-style features are arriving in production Kubernetes through 2026. Treat "who wins training" as an open bet, not a settled fact.
- **Lineage citations (stable)**: "Large-scale cluster management at Google with Borg" (EuroSys 2015); "Borg, Omega, and Kubernetes" (ACM Queue, 2016).
- **Frontier project status (for Ch 12)**: Crossplane CNCF **Graduated** (Oct 2025) — the "control plane for everything" pattern is mainstream. SpinKube (WASM workloads on K8s): CNCF Sandbox (Jan 2025), active but early — never present WASM as a default. KCP: active project, multi-tenant Kubernetes-like control planes for platform engineering. Karpenter-class node provisioning: name the pattern, make no version claims. Sources: cncf.io project pages, 2026 KubeCon EU coverage.
- The when-not-Kubernetes / tenancy / managed-vs-self-hosted content is judgment framing, not version-sensitive fact.

Facts added for the coverage-additions pass (verified Aug 2026):

- **HPA defaults**: control loop every 15s (`--horizontal-pod-autoscaler-sync-period`); tolerance 0.1 (no scale when current/target is within 10% of 1); downscale stabilization window 300s, upscale 0s; per-HPA `behavior` policies override these; per-HPA configurable `tolerance` (in `behavior`) is GA since v1.37 (alpha v1.33, beta v1.35). **Scale to zero: beta and on by default in v1.37** — `minReplicas: 0` works only with object or external metrics; the HPA records a `ScaledToZero` condition while it holds a workload at zero. The `metrics.k8s.io` API is v1 (stable) since v1.37; the HPA controller still reads v1beta1 in v1.37. Formula: `desired = ceil(current × currentMetric/targetMetric)`; HPA writes only the scale subresource.
- **Version skew**: kubelet may be up to **3 minor versions older** than kube-apiserver (since kubelet v1.25; never newer). KCM/scheduler/CCM: not newer than the API server, up to 1 minor older. HA API servers: within 1 minor of each other. kubectl: ±1 minor. Upgrade order: etcd → kube-apiserver → KCM/scheduler → kubelet.
- **ServiceAccount tokens**: projected, audience- and pod-bound tokens via the TokenRequest API; default lifetime 1h, kubelet refreshes before expiry. Auto-created Secret-based tokens are gone since v1.24 (LegacyServiceAccountTokenNoAutoGeneration).
- **CronJob**: with no `startingDeadlineSeconds`, >100 missed schedules since the last run stops the controller from starting jobs ("too many missed start time"); `startingDeadlineSeconds` bounds the counting window. `concurrencyPolicy`: Allow (default) / Forbid / Replace; Forbid skips count as missed. `timeZone` field is GA.
- **ConfigMap/Secret propagation**: mounted values refresh on the kubelet sync period (default 1 min) plus cache TTL — up to ~2 min of lag; `subPath` mounts never update; env vars never update (restart needed); immutable ConfigMaps/Secrets close the kubelet's watches and refuse edits.

Facts added for the v1.37 pass (verified 2026-09-04):

- **Pod certificates and ClusterTrustBundles: GA in v1.37** (KEP-4317, KEP-3257; `certificates.k8s.io/v1` PodCertificateRequest). Mechanism: a `podCertificate` projected volume names a signer; the kubelet generates the private key, creates a PodCertificateRequest, a signer controller fills `status.certificateChain` and `status.beginRefreshAt`, the kubelet writes key and chain into the volume (single credential-bundle file supported) and repeats at refresh time. NodeRestriction lets a node request only for pods it runs that mount that signer. A `clusterTrustBundle` projected volume delivers CA bundles by signer name or label selector. In-core signers cap lifetime at 24h; others at 91 days. No signer ships in core yet.
- **StorageVersionMigration: GA in v1.37**, `storagemigration.k8s.io/v1`, on by default; the built-in migrator controller in kube-controller-manager rewrites stored objects to the current storage version (or encryption key) and reports progress in conditions. Replaces the out-of-tree kube-storage-version-migrator.
- **Resilient watch-cache initialization: GA and locked in v1.37** (KEP-4568): while a cache warms, bounded requests are served and the rest get 429 with Retry-After instead of hitting etcd. **Concurrent watch object decode: beta, on by default in v1.37** (10 workers, ordering preserved; a CRD conversion webhook may see up to 10 concurrent calls during cache init). **etcd RangeStream: beta, on by default in v1.37** — the watch cache fills from etcd as a stream at one pinned revision; needs etcd 3.7, falls back to unary Range on older etcd.
- **Manifest-based admission control config: beta in v1.37** — webhooks and CEL policies loaded from `staticManifestsDir`, enforced from API-server startup, working while etcd is unavailable, and able to protect the in-API admission objects from modification.
- **Stale controller mitigation: beta since v1.36, extended to the HPA controller in v1.37** — a controller records the resourceVersion of its own write and requeues until its informer has caught up (read-your-writes); a circuit-breaking variant does a live GET before disruptive decisions (node lifecycle).
- **Gang scheduling / workload-aware scheduling: beta in v1.37** — Workload and PodGroup APIs in `scheduling.k8s.io/v1beta1`, workload-aware preemption, PodGroups as queue entities. The `GenericWorkload` gate is **off by default** — describe as in-tree direction, not default behavior. CompositePodGroup, Job `spec.scheduling`, and the WAS controller framework are alpha.
- **Node declared features: GA in v1.37** — `.status.declaredFeatures` on Nodes lets the control plane handle version skew per feature.
- **Container restart rules** (per-container `restartPolicy` with exit-code rules for regular containers): beta and on by default since v1.35.
- **Static pods cannot reference Secrets or ConfigMaps** (`configMapRef`, `secretRef`, and similar); the `PreventStaticPodAPIReferences` opt-out gate is removed in v1.37, so the rejection is unconditional.
- **`PodReadyToStartContainers` pod condition: GA in v1.37** (true once the sandbox and network are ready).
- **SELinuxMount and SELinuxChangePolicy: GA and on by default in v1.37** — volumes mount with `-o context=` instead of a recursive relabel when the CSIDriver sets `seLinuxMount: true`; one mount carries one context, so pods with different labels sharing a volume on one node can fail to start; `seLinuxChangePolicy: Recursive` on the pod restores the old behavior. No effect without SELinux.
- **Storage capacity scoring for dynamic provisioning: beta in v1.37** behind `StorageCapacityScoring` (off by default). **PVC `Unused` condition: beta, on by default in v1.37.** **Volume health monitor: alpha again in v1.37** (four new CSI RPCs). CSI attach limits in the cluster autoscaler: beta, opt-in.
- **StatefulSet `maxUnavailable`: on by default again in v1.37** (switched off in v1.36.x after a bug). StatefulSet `Recreate` update strategy: alpha in v1.37.
- **`metrics.k8s.io/v1`: stable in v1.37**; same schema as v1beta1; `kubectl top` prefers v1; HPA controller still uses v1beta1.
- **KYAML: stable in v1.37** — a strict YAML subset; `kubectl get -o kyaml`.
- **cAdvisor-less CRI stats: beta in v1.37 but off by default** — the kubelet summary API is still fed by cAdvisor unless `PodAndContainerStatsFromCRI` is enabled.
- **Removed or deferred**: kubelet deprecated config-flag removal is deferred to v1.38 (not done in v1.37). `kubectl run --filename` deprecated.
- **Version skew example for the upgrade question**: 1.36 → 1.37.

Writing rule: give the version only when it matters for correctness or is likely to come up in interview ("GA since v1.34"), otherwise describe behavior as current. Never describe alpha features as default behavior.
